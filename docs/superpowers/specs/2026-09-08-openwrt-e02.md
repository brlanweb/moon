# OpenWrt Host E02 Resolution

Date: 2026-09-08
Target: configured host 20, wrt, root@192.168.77.1:22.

## Root Cause

OpenWrt SNAPSHOT on Cudy TR3000 runs Dropbear 2025.89. The active daemon has no custom `-D` authorized key directory. Moon's existing installer always appended to `/root/.ssh/authorized_keys`; OpenWrt Dropbear expects `/etc/dropbear/authorized_keys` for UID 0. The first file contained the matching platform public key; the expected file did not exist. Existing source directory/file modes were 700/600, so loose permissions were not the cause for this device. Password auth succeeded; subsequent public key auth failed.

References:
- https://openwrt.org/docs/guide-user/security/dropbear.public-key.auth
- https://raw.githubusercontent.com/openwrt/openwrt/main/package/network/services/dropbear/patches/100-pubkey_path.patch

## Scoped Changes

- Created the previously absent `/etc/dropbear/authorized_keys` with only the already-authorized-for-installation Moon public key selected by SHA-256 of its type and key blob. Did not copy the other unrelated key from the old file.
- Original `/root/.ssh/authorized_keys` preserved. New file mode 600. Installer normalizes containing directory mode to 700 (previously 755).
- No router reboot, Dropbear restart, password policy change, weakened signature algorithms or private-key export.
- After real platform host verification succeeded, set only host 20 `is_verified` to true.
- Updated `SSH.add_public_key` to recognize Dropbear + remote UID 0 + OpenWrt marker and choose the proper default path. OpenSSH and non-root users keep their home directory path. Added safe quoting, separate lines, exact-line deduplication and permission normalization.

## Verification

- Before: Moon's actual Host.get_ssh() failed AuthenticationException.
- After: same stored private key succeeded; remote `id -u` returned 0, exit 0.
- Router log: `Pubkey auth succeeded for 'root'` at 20:26:26, matched to the controlled verification.
- Two calls to repaired installer preserved authorized_keys checksum.
- Actual `_do_host_verify` returned true without supplying a password.
- 8 focused tests pass under the running container's Python 3.10 / Paramiko 2.11 environment. Syntax check and git diff --check pass. Independent static review found no blocking issue.

## Rollback Boundary

The destination file did not exist before the repair. Reverting the router change means removing only that newly created file, only after confirming no other keys have been added to it since, and restoring the directory's former mode 755. This would intentionally remove Moon's working key access. Preserve the original home authorized_keys and current password access. No rollback executed.
