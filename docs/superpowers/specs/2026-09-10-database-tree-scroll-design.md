# `/db` 数据库目录滚动修复设计

## 背景

数据库终端使用左右双栏布局。左侧依次包含 Logo、连接标题、搜索框和数据库对象树。连接数据库并展开大量表后，数据库对象树会撑高外层页面，无法形成独立滚动区域，用户因此无法查看底部表项。

## 根因

页面外层容器当前使用 `min-height: 100vh`。当数据库对象树内容超过视口时，Flex 容器可以继续增长，树组件所在的 `.tree` 元素没有获得受约束的可用高度。虽然 `.tree` 已设置 `overflow: auto`，但内容没有溢出一个固定高度的盒子，所以浏览器不会显示有效的纵向滚动区域。

## 设计

采用纯 CSS 的最小修复：

- 将页面外层容器固定为 `height: 100vh`。
- 在页面外层容器设置 `overflow: hidden`，阻止数据库对象树带动整个页面纵向增长。
- 将左侧栏高度约束为父容器高度，并保留纵向 Flex 布局。
- 为左侧栏设置 `min-height: 0`，允许数据库对象树在 Flex 布局中收缩。
- 数据库对象树继续使用 `flex: 1`、`min-height: 0` 和 `overflow: auto`，成为唯一的左侧纵向滚动区域。
- Logo、连接标题、工具按钮和搜索框保持固定，不跟随数据库对象树滚动。
- 右侧查询标签页、SQL 编辑器和结果区域保持现有行为。

不引入 JavaScript 高度计算，不改变数据库元数据接口、树节点结构或连接交互。

## 验收标准

1. `/db` 页面整体高度等于浏览器视口高度，不产生由左侧目录导致的页面纵向滚动。
2. 展开超过可视高度的数据库表目录后，左侧目录区域可以通过鼠标滚轮、触控板或滚动条上下滚动。
3. 能够滚动到目录中的最后一个表节点并进行选择。
4. 滚动目录时，Logo、连接标题、操作按钮和搜索框保持可见。
5. 表目录较少时不出现无意义的纵向滚动条。
6. 右侧 SQL 编辑器和查询结果区域布局不回归。

## 验证方式

- 添加样式回归测试，验证工作台和侧栏具备明确的视口高度约束，目录区域保留 Flex 收缩和滚动规则。
- 运行数据库页面相关前端测试。
- 执行前端生产构建。
- 使用 Playwright 在桌面视口构造大量树节点，验证目录区域的 `scrollHeight` 大于 `clientHeight`，滚动后可见并可选中最后一个表节点。
- 截图检查左侧固定区域和右侧工作台不存在重叠或异常位移。

## 风险与回滚

风险仅限 `/db` 页面布局样式。若出现布局回归，恢复外层容器和侧栏的高度、溢出规则即可；不涉及后端接口、数据库结构或用户数据。
