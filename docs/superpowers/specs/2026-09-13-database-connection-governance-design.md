# 数据库连接治理与生产安全设计

日期：2026-09-13

## 目标

在保持现有请求级数据库连接模型的前提下，补齐连接断开、高级超时、空闲自动断开、只读保护、环境分级、生产写操作确认和标准连接 URI 导入。VPN 能力本期只预留可复用网络配置边界，不实现 OpenVPN/WireGuard 建链。

## 已确认范围

- 采用方案 A：继续使用请求级连接，不增加常驻数据库连接池。
- “断开连接”是前端逻辑断开：关闭标签、清理元数据缓存和编辑状态；后端连接本来就会在每次请求结束后关闭。
- 空闲断开时间按连接配置，`0` 表示禁用自动断开。
- 生产环境对数据变更语句二次确认，不扩大到所有 DDL。
- VPN 管理后续单独实现。

## 数据模型

`DatabaseConnection` 新增：

- `connect_timeout`：连接超时秒数，默认 10，允许 1～120。
- `query_timeout`：查询超时秒数，默认 30，允许 1～3600。
- `idle_timeout`：前端逻辑连接空闲超时分钟数，默认 30，`0` 表示禁用。
- `read_only`：只读模式，默认关闭。
- `environment`：`normal` 或 `production`，默认 `normal`。

通过 Django migration 增量升级，不修改现有连接记录的账号密码和类型。

## 后端连接行为

各数据库驱动从连接记录读取连接与查询超时：

- MySQL/MariaDB：`connect_timeout`、`read_timeout`、`write_timeout`。
- PostgreSQL：`connect_timeout` 和 `statement_timeout`。
- ClickHouse：`connect_timeout`、`send_receive_timeout`。
- Redis：`socket_connect_timeout`、`socket_timeout`。

测试连接、元数据查询和命令执行继续使用上下文关闭连接，异常时不保留连接对象。

## SQL 安全策略

新增独立语句分类模块，负责解析命令中的多条 SQL，并返回是否只读、是否包含数据变更及语句类型。使用 `sqlparse` 处理注释、空白、多语句和常见 CTE，避免用简单前缀判断。

只读连接：

- SQL 数据库只允许查询、解释和元数据读取语句。
- 拒绝 INSERT、UPDATE、DELETE、REPLACE、MERGE、COPY 写入、LOAD、CALL 以及 DDL/DCL。
- Redis 只允许明确的只读命令集合；未知命令按写操作拒绝。
- 后端强制校验，前端提示只用于改善体验。

生产环境：

- INSERT、UPDATE、DELETE、REPLACE、MERGE、UPSERT、COPY 写入、LOAD DATA 等数据变更要求二次确认。
- 第一次执行返回结构化 `requires_confirmation` 响应，不执行语句。
- 前端展示连接、环境和待执行语句，用户确认后携带后端签名的一次性确认令牌重试。
- 令牌绑定用户、连接 ID 和语句摘要，并设置短时有效期，防止确认内容与实际执行内容不一致。

## 前端交互

连接菜单新增“断开连接”。执行后：

- 关闭该连接的工作标签。
- 清除目录元数据、编辑命令和展开状态。
- 清除该连接的最后活动时间。
- 下次点击重新请求元数据。

高级设置放在连接表单的折叠区域：连接超时、查询超时、空闲断开、只读模式和环境。生产环境及只读状态在连接树和查询面板显示明确标签。

用户执行生产数据变更时使用确认弹窗；取消不发送第二次请求。只读连接的运行按钮仍可用于 SELECT，写语句由后端拒绝并显示原因。

## 空闲断开

前端维护每个已打开连接的最后活动时间。打开连接、切换到连接、编辑或执行命令时刷新时间。定时检查超过该连接 `idle_timeout` 的标签，调用与手动断开相同的清理逻辑，并显示提示。由于后端不保存会话，这一设置不声称终止一个不存在的常驻连接。

## 标准连接 URI 导入

连接表单提供“导入连接 URI”入口，单次解析一个标准 URI 并填充表单，用户确认后再保存。支持：

- `mysql://`、`mariadb://`
- `postgres://`、`postgresql://`
- `clickhouse://`、`clickhouses://`
- `redis://`、`rediss://`

解析用户名、密码、主机、端口、数据库和 SSL 标识。对 URL 编码内容使用标准 `URL` API 解码；不识别的参数忽略，不保存原始 URI。编辑已有连接时，导入 URI 视为覆盖表单中的连接参数。

## VPN 扩展边界

本期不启动系统 VPN，不处理 OpenVPN 配置文件，也不要求容器具备 `NET_ADMIN`。数据模型暂不增加无效的 VPN 字段。

后续单独增加可复用 `NetworkProfile`：一个网络配置可关联多个数据库连接，连接请求通过受控网关或独立 sidecar 执行。OpenVPN/WireGuard 配置、密钥、运行状态和健康检查由网络配置模块管理，不塞进数据库客户端。该阶段实施前必须确认部署拓扑、权限、路由隔离和断线回收策略。

## 测试与验证

后端覆盖：

- 新增字段默认值、校验和迁移。
- 各驱动收到连接级超时参数。
- SQL 与 Redis 只读策略，包括注释、多语句和 CTE。
- 普通环境直接执行、生产数据变更返回确认挑战、有效令牌执行、篡改或过期令牌拒绝。
- URI 解析的协议、编码、IPv6、缺省端口和错误输入。

前端覆盖：

- 手动断开清理标签和缓存。
- 空闲连接自动断开，`0` 不自动断开。
- 高级字段保存和回显。
- URI 导入填充表单。
- 生产数据变更弹出确认，取消不执行，确认后携带令牌重试。

最终运行数据库后端测试、前端数据库模块测试和前端生产构建。

## 非目标

- 不增加后端常驻连接池。
- 不实现事务会话跨请求保持。
- 本期不实现 OpenVPN、WireGuard 或系统路由变更。
- 不把前端校验作为数据库安全边界。
